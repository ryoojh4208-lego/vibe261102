# PRD: 오늘의 할일 (Today's To-Do) 웹페이지

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 (초안) |
| 작성일 | 2026-11-02 |
| 상태 | 설계 단계 (구현 전) |

---

## 1. 개요

### 1.1 배경
하루 단위로 해야 할 일을 빠르게 적고, 완료 여부를 체크하며, 하루를 정리할 수 있는 가볍고 단순한 웹페이지가 필요하다. 복잡한 프로젝트 관리 도구 대신 "오늘"에 집중하는 도구를 목표로 한다.

### 1.2 목표
- 3초 안에 할일 하나를 추가할 수 있을 만큼 단순한 UX
- 별도 설치·로그인 없이 브라우저에서 바로 사용
- 새로고침하거나 브라우저를 다시 열어도 데이터 유지
- PC와 모바일 모두에서 편하게 사용

### 1.3 비목표 (이번 범위 아님)
- 회원가입/로그인, 서버 동기화, 다중 기기 공유
- 팀 협업, 할일 할당, 댓글
- 반복 일정, 캘린더 연동, 푸시 알림

## 4. 기능 요구사항

### 4.1 헤더 영역
- **FR-01** 오늘 날짜를 `2026년 11월 2일 (월)` 형식으로 표시한다.
- **FR-02** 진행률을 `3 / 5 완료` 텍스트와 진행 바(progress bar)로 표시한다.
- **FR-03** 모든 할일 완료 시 축하 메시지(예: "오늘 할일을 모두 끝냈어요! 🎉")를 표시한다.

### 4.2 할일 추가
- **FR-04** 상단 입력창에 텍스트 입력 후 Enter 또는 [추가] 버튼으로 추가한다.
- **FR-05** 공백만 있는 입력은 추가하지 않는다 (앞뒤 공백 trim).
- **FR-06** 최대 길이 100자. 초과 시 입력을 제한한다.
- **FR-07** 추가 후 입력창은 비워지고 포커스가 유지된다 (연속 입력 가능).
- **FR-08** (P1) 추가 시 우선순위를 선택할 수 있다. 기본값은 "보통".

### 4.3 할일 목록
- **FR-09** 각 항목은 체크박스, 내용, 우선순위 표시, 삭제 버튼으로 구성된다.
- **FR-10** 체크 시 완료 상태로 전환되며 취소선 + 흐린 색으로 표시된다. 다시 체크하면 미완료로 돌아간다.
- **FR-11** 정렬 기본 규칙: 미완료 항목이 위, 완료 항목이 아래. 같은 그룹 내에서는 생성 순.
- **FR-12** 목록이 비어 있으면 빈 상태 안내("오늘 할 일을 추가해 보세요")를 표시한다.

### 4.4 할일 수정 (P1)
- **FR-13** 항목 내용을 더블클릭(모바일: 수정 버튼)하면 인라인 편집 모드로 전환된다.
- **FR-14** Enter 또는 포커스 해제 시 저장, Esc 시 취소. 빈 내용으로 저장하면 기존 값을 유지한다.

### 4.5 할일 삭제
- **FR-15** 삭제 버튼 클릭 시 즉시 삭제한다.
- **FR-16** (P1) 삭제 직후 하단에 "삭제됨 · 되돌리기" 토스트를 5초간 표시한다.
- **FR-17** (P1) [완료 항목 지우기] 버튼으로 완료된 항목을 일괄 삭제한다 (확인 대화상자 표시).

### 4.6 필터 (P1)
- **FR-18** [전체] [진행 중] [완료] 탭으로 목록을 필터링한다.
- **FR-19** 선택된 필터는 저장되어 재방문 시 유지된다.

### 4.7 날짜 처리
- **FR-20** 할일은 생성 날짜(`date`, YYYY-MM-DD, 로컬 시간 기준)를 가진다.
- **FR-21** 메인 화면에는 **오늘 날짜**의 할일만 표시한다.
- **FR-22** (P2) 날짜가 바뀌면 이전 날짜의 미완료 할일 개수를 알려주고 "오늘로 가져오기"를 제안한다.

### 4.8 데이터 저장
- **FR-23** 모든 데이터는 브라우저 `localStorage`에 저장한다.
- **FR-24** 추가/수정/삭제/체크 시 즉시 저장한다.
- **FR-25** 저장 데이터가 손상되었거나 `localStorage`를 사용할 수 없으면 빈 목록으로 시작하고 앱은 정상 동작한다 (메모리 모드).

### 6.3 디자인 가이드
- 콘셉트: **"춘식이와 고구마"** — 노란색·갈색 위주의 따뜻하고 귀여운 분위기
- 최대 폭 600px 중앙 정렬 카드 레이아웃, 둥근 모서리(20px), 크림색 도트 배경
- 폰트: 제목은 둥글고 귀여운 `Jua`(Google Fonts), 본문은 Pretendard → system-ui
- 색상은 CSS 변수로 정의하고 다크 모드(짙은 갈색 배경)도 같은 변수로 지원

| 토큰 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `--bg` | `#FFF4CC` 크림 노랑 | `#241811` 짙은 갈색 | 페이지 배경 |
| `--card` | `#FFFDF5` | `#33241A` | 카드 |
| `--primary` | `#FFC93C` 노랑 | `#FFC93C` | 버튼, 체크, 진행 바 |
| `--text` | `#4A2E1A` 갈색 | `#FBE9C8` | 본문 |
| `--text-muted` | `#9C7B5E` | `#C9A97F` | 보조 텍스트 |
| `--border` | `#EAD3A2` | `#4E3826` | 테두리 |
| 우선순위 | 높음 `#B5452F`(고구마) · 보통 `#F2A900`(노랑) · 낮음 `#C9B79C`(베이지) | | 점 표시 |

- 체크/삭제 시 짧은 전환 애니메이션(150~200ms), 캐릭터는 살짝 통통 튀는 애니메이션

### 6.4 캐릭터 연출
캐릭터는 인라인 SVG `<symbol>`로 직접 그려 `index.html`에 넣는다 (외부 이미지 없음).

| 위치 | 연출 |
|---|---|
| 헤더 | 제목 옆에 춘식이 얼굴, 오른쪽 끝에 고구마가 빼꼼 |
| 진행 바 | 춘식이가 진행률만큼 바 위를 이동하고, 끝에는 고구마가 기다림 |
| 전부 완료 | 춘식이가 웃는 얼굴로 고구마 옆에 + "오늘 할일을 모두 끝냈어요! 🎉" |
| 빈 목록 | 꾸벅꾸벅 조는 춘식이 + 고구마 + "오늘 할 일을 추가해 보세요" |
| 우선순위 "높음" | 빨간 갈색 고구마 색 점 |

> 춘식이는 카카오의 캐릭터이므로, 개인 사용 범위를 넘어 공개 배포할 경우 IP 사용 허가를 확인한다.

## 7. 데이터 모델

### 7.1 Todo 객체
```ts
interface Todo {
  id: string;            // crypto.randomUUID()
  text: string;          // 1~100자
  completed: boolean;
  priority: 'high' | 'medium' | 'low';   // 기본 'medium'
  date: string;          // 'YYYY-MM-DD' (로컬 기준 생성일)
  order: number;         // 수동 정렬용 (P2)
  createdAt: number;     // epoch ms
  completedAt: number | null;
}
```

### 7.2 localStorage 스키마
| Key | 값 | 설명 |
|---|---|---|
| `todolist:v1:todos` | `Todo[]` (JSON) | 전체 할일 목록 |
| `todolist:v1:settings` | `{ filter: 'all' \| 'active' \| 'done', theme: 'light' \| 'dark' \| 'system' }` | 사용자 설정 |

- 키에 버전(`v1`)을 포함하여 향후 스키마 변경 시 마이그레이션 가능하도록 한다.
- 30일이 지난 완료 항목은 앱 시작 시 자동 정리(선택, P2).

## 8. 기술 설계

### 8.1 기술 스택
| 항목 | 선택 | 이유 |
|---|---|---|
| 마크업/스타일 | HTML5 + CSS3 (CSS 변수, Flexbox) | 의존성 없는 가벼운 구성 |
| 스크립트 | Vanilla JavaScript (ES Modules) | 빌드 도구 없이 브라우저에서 바로 실행 |
| 저장소 | localStorage | 서버 불필요 |
| 배포 | 정적 호스팅 (GitHub Pages 등) 또는 로컬 파일 | 간단한 배포 |

> 향후 기능이 커지면 React/Vite 전환을 고려하되, MVP는 Vanilla JS로 진행한다.

### 8.2 폴더 구조 (예정)
```
todolist/
├── prd.md          # 본 문서
├── index.html      # 페이지 마크업
├── css/
│   └── style.css   # 스타일, 테마 변수
└── js/
    ├── app.js      # 진입점, 이벤트 바인딩
    ├── store.js    # 상태 관리 + localStorage 입출력
    ├── render.js   # DOM 렌더링
    └── utils.js    # 날짜 포맷, id 생성 등
```

### 8.3 아키텍처 (단방향 데이터 흐름)
```
 사용자 이벤트 ──▶ app.js (액션 호출)
                     │
                     ▼
               store.js (상태 변경 → localStorage 저장)
                     │  subscribe
                     ▼
               render.js (상태 → DOM 갱신)
```
- **store**: `getState()`, `addTodo(text, priority)`, `toggleTodo(id)`, `updateTodo(id, patch)`, `deleteTodo(id)`, `clearCompleted()`, `setFilter(filter)`, `subscribe(listener)`
- **render**: 상태를 받아 목록·헤더·필터를 다시 그림. 이벤트는 목록 컨테이너에 위임(event delegation)
- 텍스트 출력은 `textContent`만 사용

## 10. 인수 기준 (MVP)

- [ ] 텍스트 입력 후 Enter 시 미완료 그룹의 끝(생성 순)에 항목이 추가된다.
- [ ] 공백 입력은 추가되지 않는다.
- [ ] 체크 시 취소선이 표시되고 완료 그룹으로 이동하며, 진행률이 즉시 갱신된다.
- [ ] 삭제 시 항목이 사라지고 진행률이 갱신된다.
- [ ] 새로고침 후에도 목록과 완료 상태가 그대로 유지된다.
- [ ] 다음 날 접속 시 오늘 날짜의 빈 목록이 표시되고, 이전 데이터는 손실되지 않는다.
- [ ] `<script>` 등 HTML을 입력해도 텍스트로만 표시된다.
- [ ] 모바일(360px)에서 가로 스크롤 없이 모든 기능을 사용할 수 있다.
- [ ] Tab/Enter/Space 키만으로 추가·체크·삭제가 가능하다.

## 12. 리스크 및 고려사항
